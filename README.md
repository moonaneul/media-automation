# 하늘빛기쁨성서침례교회 미디어 자동화

하늘빛기쁨성서침례교회의 주간 예배 자료 제작 업무를 자동화하기 위한 프로젝트입니다.

현재 미디어팀은 매주 다음 자료를 제작합니다.

- 수요예배 PPT
- 금요기도회 PPT
- 주일예배 PPT
- 주일 주보

이 프로젝트의 목표는 단순히 PPT 제작 시간을 줄이는 것이 아니라,

> 목사님·찬양리더 등 정보 제공자가 필요한 내용을 입력하면 시스템이 예배 자료를 생성하고, 미디어팀은 제작보다 최종 검수에 집중하는 구조

를 만드는 것입니다.

---

## 목표

최종적으로 다음과 같은 흐름을 지향합니다.

```text
목사님 / 찬양리더 / 담당자
        ↓
이번 주 예배 정보 입력
        ↓
구조화된 Weekly Data
        ↓
제작 엔진
        ↓
수요 PPT
주일 PPT
주보 PDF
금요기도회 자료
        ↓
자동 검수
        ↓
미디어팀 최종 확인
```

사람의 검수를 완전히 제거하는 것이 목표는 아닙니다.

목표 수준은 다음과 같습니다.

```text
자동 생성
→ 자동 검수
→ 사람이 짧게 최종 확인
→ 실제 예배 사용
```

# 핵심 설계

## 1. Weekly Data

수요·주일·주보에서 필요한 정보를 구조화된 데이터로 관리합니다.

특히 입력값은 다음 상태를 구분합니다.

```text
UNSET = 아직 정보가 전달되지 않음
NONE  = 이번 주에는 해당 항목이 없음
VALUE = 이번 주 사용할 값이 있음
```

지난주 값을 자동으로 승계하지 않습니다.

세부 규칙은 `AGENTS.md`를 따릅니다.

---

## 2. 블록 기반 조립

과거 한 주의 PPT 전체를 복사하고 텍스트만 바꾸는 방식보다
필요한 블록을 순서대로 조립하는 방식을 사용합니다.

예:

```text
고정 예배 안내
→ 빈 화면
→ 찬양 원본 슬라이드
→ 빈 화면
→ 기도
→ 빈 화면
→ 성경 본문
→ 빈 화면
→ 설교 제목
→ ...
```

곡마다 악보 슬라이드 수가 다르고,
성경 본문 절 수도 매주 달라지므로
최종 PPT의 슬라이드 수는 고정하지 않습니다.

---

## 3. 찬양 자료

수요·주일·금요 대면 예배에서는
가사만 있는 PPT가 아니라 기존 악보 PPT를 사용하는 것을 원칙으로 합니다.

기본 우선순위:

```text
사용자가 직접 제공한 정상 악보 PPT
        ↓
검수된 교회 보관 자료
        ↓
정상적인 외부 악보 PPT
        ↓
자료 없음
```

자료가 없는 경우 비슷한 곡이나 가사 PPT를 임의로 만들어 대체하지 않습니다.

향후 검수된 자료를 재사용할 수 있도록
찬양 라이브러리를 구축할 수 있지만,
저장 위치와 관리 방식은 아직 확정하지 않았습니다.

---

## 4. 성경 본문

성경 본문은 개역개정을 기준으로 생성합니다.

수요·주일은 기본적으로:

```text
한 절 = 한 슬라이드
```

구조를 사용합니다.

본문 생성, 절 번호 검수, `세례 → 침례` 등의 상세 제작 규칙은 `AGENTS.md`를 따릅니다.

---

## 5. 주일 PPT와 주보의 공통 데이터

같은 주의 주일 PPT와 주보를 따로 입력하지 않고,
공통되는 정보는 동일한 Weekly Data를 사용하도록 설계합니다.

예:

- 날짜
- 본문
- 설교 제목
- 찬양
- 기도 담당자
- 봉헌기도 담당자
- 특송
- 교회 소식
- 오후예배 정보

이를 통해 PPT와 주보 사이의 불일치를 줄이는 것이 목표입니다.

# 주일 PPT와 주보의 전달 주보 공통 입력

같은 주 전달 주보는 한 번만 등록합니다. `sunday.py bulletin`과
`bulletin.py start`는 모두 `input/bulletin/YYYYMMDD/transfer.hwp|hwpx|txt`를
사용합니다. 주일 PPT 쪽은 이 원본에서 필요한 텍스트를 읽고, 주보 PDF도
같은 원본과 같은 주간 데이터를 사용합니다.

```text
python sunday.py bulletin 2026-10-04 전달_주보.hwp
python sunday.py resume 2026-10-04
python bulletin.py status 2026-10-04
python bulletin.py number 2026-10-04 <확인된호수>  # 해당 주 호수가 확인된 경우에만
python bulletin.py complete 2026-10-04
```

수정된 전달 주보는 `--replace`를 명시해야 교체됩니다. 날짜가 다르면 원본
등록과 산출을 중단하며 기존 등록본은 유지합니다. 주일예배 안내에 명시된
값이 우선이고, PPT의 `교회 소식 있음` 표시는 전달 주보의 상세 광고로
보완됩니다. 주보 생성 전에 같은 주의 주일 데이터와 전달 주보를 자동
대조하여 오래된 주일 데이터가 있으면 `sunday.py resume`을 요청합니다.
주보 PDF에서는 검증된 주일 데이터를 다시 덮어쓰지 않습니다. 찬양 원문은
개별 악보 슬롯에 임의 배정하지 않으며, 주보 호수도 과거 번호에서 추정하지
않습니다.

다음 개발 항목은 실제 주간 자료에서 주일 PPT와 주보 PDF의 공통 항목 및

실행 중인 8876 서버는 재시작하지 않았으므로 코드 변경은 다음 재시작 때 적용된다.

### 실사용 DB와 경로 통합
