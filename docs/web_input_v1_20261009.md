## 작업 화면

`python webapp.py`로 로컬 웹앱을 실행하면 다음 순서로 보인다.

1. 종류와 날짜로 새 작업을 만든다. 이전 주 입력은 자동 복사하지 않는다.
2. 자료 유형·곡/미디어 슬롯·파일을 고른다. 웹에서 임의 저장 경로를 요구하지 않는다. 백엔드에서 등록 유형, 서비스, 슬롯, 확장자를 검증하고 정해진 경로에 저장한다.
3. 해당 작업의 등록 자료, 미등록 필수 자료, 미확인 안내 필드(UNSET/NONE/VALUE)를 본다.
4. 필수자료가 부족하거나 검토되지 않은 안내 문장이 있으면 제작 실행을 막는다.
5. 실제 제작 CLI에서 추가 입력 또는 본문·미디어 문제가 발견되면 기존 방식대로 실패 처리하고 산출물은 노출하지 않는다.

### 업로드 유형

- 주일: 안내 TXT, 수정 안내 TXT, 전달 주보 HWP/HWPX/TXT, 예배 전 안내 PPTX, 7개 악보 슬롯, 검토된 주일 안내 해석 YAML, 개역개정 JSON.
- 주보: 전달 주보, 같은 주 주일 안내 해석 YAML·기본 YAML·통합 YAML, **직접 확인한 호수 입력**.
- 수요: 안내 TXT, 수정 안내 TXT, 원본 PPTX, 5개 악보 슬롯, 검토된 수요 안내 해석 YAML, 개역개정 JSON.
- 금요 Zoom: 안내 TXT, 수정 안내 TXT, 참고 원본 PPTX, 5개 MP4/4개 MP3와 예배 전 선택 음원, 검토된 안내 해석 YAML, 주간 YAML, 본문 YAML, 미디어 체크리스트.

각 입력은 업로드 순간 **파일 존재만** 확인한다. 파일 내용과 성경 번역의 진위, 검수된 악보인지, 영상 사용 허락 여부는 업로드 자체로 확인되지 않는다. 금요 대면 PPT 제작은 구현 범위 밖이다. 금요 참고 원본은 저장만 하며 자동 병합하지 않는다.

## 상태 / 안전

- 파싱된 안내의 `provided` 또는 `asset_required` → VALUE, `blank` → NONE, `missing` → UNSET. 실제 빈 값에 지난주 값을 넣지 않는다.
- 주일·수요·금요의 핵심 항목이 UNSET이면 생성 전 차단한다. 설교 제목이나 대표 본문이 NONE이면 차단한다.
- 안내의 날짜와 작업 날짜가 다르거나 REVIEW 필요 상태이면 차단한다.
- 수정 안내는 `revision_001.txt`, `revision_002.txt` …로 원본을 보존하며 기존 해석 YAML보다 최신인 수정 안내가 있으면 제작을 차단한다. **수정 안내를 자동 해석/병합하지는 않는다.** 수정한 해석 자료는 새 작업에 등록해야 한다.
- 주보 호수는 명시적으로 입력받고 `state.yaml`로 저장한다. 날짜로 추정하지 않는다. 기존 값을 조용히 덮어쓰지 않는다.
- 임의 경로 직접 입력 필드는 웹 화면에서 제거했다. 구형 `/api/jobs/<id>/files?path=...` 엔드포인트는 개발·이전 호환을 위해 남아 있으나 웹 사용자 흐름에는 표시하지 않는다. **현재 시스템은 127.0.0.1 전용이며 외부 공개 금지.**
- 원본 `.ppt`를 Mac에서 PPTX로 자동 변환하지 않는다. 기존 운영 흐름의 PPTX 변환 후 등록한다.

## 신규 API

- `GET /api/jobs/<id>/input-types` — 서비스별 자료 유형·허용 확장자·슬롯.
- `POST /api/jobs/<id>/typed-files?kind=...&filename=...&slot=...` — 본문은 원시 파일 바이트, 대상 저장 경로 자동 지정.
- `POST /api/jobs/<id>/bulletin-number` — `{ "number": "13-40" }`.
- 기존 작업 상세 `GET /api/jobs/<id>`에 `requirements` 추가(`ready`, `present`, `missing`, `checks`, `fields`, `note`).

## 후속 범위와 검수 한계

본 단계는 입력 폼/등록/기초 필수 입력 게이트를 연결한 것이다. 안내 TXT → 최신 지시 누적 파싱 → 최종 공통 SundayData 구성 → 주보/PPT 교차검수 → 생성 및 시각 미리보기 → 사람의 확인/기록은 **아직 연결되지 않았다**. 특히 업로드한 해석 YAML은 기존 CLI가 산출한 검토 완료 자료여야 한다. 준비되지 않은 YAML로부터 내용이 자동 생성된다고 가정하지 않는다. 실제 `.hwp/.hwpx` 파싱, 질문 원문 4개, 본문과 노래 정합성은 기존 제작기에서 추가 검증한다. 금요 MP3 공통 음원 대체 지원도 현재 웹 선검증에는 연결되지 않아 주간별 4개의 MP3 등록을 요구한다.
