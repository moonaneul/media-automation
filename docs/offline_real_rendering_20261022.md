# 합성 자료를 사용한 실제 PPTX/PDF 생성·렌더링 검증 — 2026-10-22

## 목적 및 범위

- **실제 `generate()` 및 `generate_bulletin()` 함수를 호출하여 파일을 생성**했다. 이전 오프라인 Worker 작업흐름 테스트처럼 결과 생성 자체를 Mock으로 대체하지 않았다.
- 수요 PPT(4:3), 주일 PPT(4:3), 금요 대면 PPT(4:3), 금요 Zoom PPT(16:9), 주일 주보 PDF(A4 가로 2쪽)를 검사했다.
- 테스트 생성기: `tests/test_isolated_real_rendering.py`. CI: `.github/workflows/offline-real-rendering.yml`.
- 시험 입력은 가상 주간 날짜 `2026-10-25`, 가짜 설교 제목/담당자/질문, 가짜 본문 `요 3:16~17` 주소와 **실제 개역개정 내용이 아닌 합성 문장**, 새로 생성한 PPT 시작 화면, 새로 생성한 빈 A4 가로 PDF 2면으로만 구성했다. **실제 교회 악보·영상·성경 원문·주보 원본 PDF/PNG를 복사하지 않았다.**
- 예배용으로 사용할 수 있는 결과물을 만들거나 실제 교회 예배 입력을 변경한 것이 아니다. 테스트 중 네트워크 요청은 Python socket 단위에서 차단한다. GitHub CI는 Cloud 인증/GCP WIF/Supabase/OneDrive 자격 증명이 없는 별도 워크플로다.

모든 찬양 원본은 **미제공으로 처리**, 악보가 없으면 빈 슬라이드를 생성하고 `:score_asset`을 누락 기록에 남김. 가사만 넣거나 과거 악보를 자동 승계하지 않음. 합성 본문에 포함된 `세례`는 출력에서 `침례`로 바뀌는지 확인하되 **개역개정 원문의 정확성 검증은 아님**.

PPT는 `python-pptx`로 구조 확인 후 **LibreOffice에서 실제 PDF로 렌더링**했고, 주보 PDF는 **PyMuPDF로 실제 페이지 픽셀을 렌더링**했다.
