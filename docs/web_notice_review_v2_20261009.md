# 로컬 웹 입력 v2 — 안내 해석·수정 누적과 같은 주 주일 데이터 공유

날짜: 2026-10-09. 기준: 전달 코드 스냅샷(이전 웹 입력 v1 반영본). **원본 맥/GitHub에 직접 적용한 커밋이 아니다.** 확정 주보 레이아웃·디자인 자산·렌더링 코드는 변경하지 않았다. 실제 10/11 예배 안내가 없어 예배물은 제작하지 않았다.

## 이번 단계에 연결한 기능

1. 주일·수요·금요 Zoom 작업에서 `initial.txt`가 등록되면 기존 예배별 `scripts/parse_*_notice.py`를 이용한 **안내 초안 미리보기**를 제공한다.
2. 해당 작업의 `revision_001.txt`부터 번호순으로 누적 파싱한다. `missing`은 기존 같은 주 항목을 유지하고, 실제 제공된 `provided` / `blank` / `asset_required`만 해당 필드에 반영한다. `blank`는 명시적 NONE이며 과거 값을 복구하지 않는다.
3. 화면에 **UNSET / NONE / VALUE, 실제 값, 마지막 변경 출처**를 표시한다. 파서가 알 수 없는 문장이나 일치하지 않는 날짜는 자동 확정하지 않는다. 수정 지시의 다중 찬양 곡 수 표현은 기존 슬롯을 덮지 않고 검토 필요로 분류한다.
4. 모든 필수 안내 항목이 확인된 경우에만 운영자가 **안내 해석 확인·확정** 버튼을 눌러 새 `output/{service}_intake/..._intake.yaml` 파일을 생성한다. 기존 해석 YAML이 있으면 덮어쓰지 않는다.
5. 생성한 YAML의 `web_review.confirmed_sources`에 원문·수정 안내의 경로와 SHA-256을 기록한다. 이후 안내 파일 구성/내용이 달라지면 제작 사전 점검에서 불일치로 차단한다.
6. 주일·주보 작업의 **동일 주차 주일 공통 정보 미리보기**를 추가했다. 주일/주보 작업 폴더는 서로 독립적으로 유지한다. 주보 작업에서 생성 완료된 **동일 날짜 주일 작업을 명시적으로 선택한 경우에만** 검증된 안내 해석, 기본 데이터, 주간 통합 YAML 3개를 가져온다. 이전 주 또는 결과 미생성 작업은 거부한다. 대상에 해당 파일이 이미 있으면 변경/덮어쓰기하지 않는다. 출처 작업 ID와 SHA-256을 주보 작업 메타데이터에 기록한다.
7. 주보 제작 전에는 주일 안내 상태와 날짜, 기본/통합 주일 데이터의 날짜, **명시적으로 제공된 설교 제목·본문과 통합 YAML의 일치 여부**를 확인해 불일치를 차단한다.

## API v2

기존 `GET /api/jobs/<id>`의 `requirements`와 v1 엔드포인트를 유지한다.

- `GET /api/jobs/<id>/notice-preview` — 주일·수요·금요 안내 초안과 출처/미확인 항목.
- `POST /api/jobs/<id>/confirm-notice` — 미해결 상태가 없고 기존 해석 파일이 없는 경우에만 확정 YAML 신규 생성.
- `GET /api/jobs/<id>/sunday-common` — 주일/주보에 등록된 같은 주 공통 항목과 불일치.
- `POST /api/jobs/<bulletin_id>/import-sunday-week` — JSON `{"sunday_job_id":"..."}`. 같은 날짜에 generated인 Sunday 작업의 입력 3개만 명시적으로 복사.

## 의도적인 제한

- 파서가 자동 해석하지 못한 문장은 현재 웹에서 바로 분류/무시하지 않는다. **이 경우 자동 확정 차단**이며 기존 CLI의 수동 REVIEW 흐름이 필요하다.
- 수정 안내에서 다중 찬양 곡 수 같은 모호한 표현을 자동 병합하지 않는다. 명확한 개별 곡 슬롯 수정으로 전달받거나 사람이 검토해야 한다.
- 확정된 해석 YAML을 웹에서 덮어쓰지 않는다. 후속 수정이 있으면 **새 작업에서** 안내 및 수정 지시를 등록·검토한다.
- 금요 대면 작업은 여전히 이 단계의 대상이 아니다. Zoom의 공통 음원 대체 규칙과 실제 MP4/MP3 재생은 별도 검수다.
- `provided`의 상태 확인은 곡명·본문의 실제 정확성, 개역개정 절 확인, 악보 사용 허락 또는 프린터·미디어 실제 검수를 뜻하지 않는다.
- 주보의 전달 HWP/HWPX 원문을 웹에서 직접 해석하거나, 목장 질문 4개와 광고/오후예배/모든 찬양을 PPT와 **전체 자동 교차검수한 것은 아니다**. 현재 명시 항목 일부의 사전 대조와 기존 CLI의 전달 주보 정합성 검증을 분리해서 사용한다.
- 사용자 승인 주보 디자인은 변경하지 않았다. PDF 실물 양면 인쇄 및 접지 검수, PPT 육안/맥 PowerPoint 실행, 금요 미디어 재생은 하지 않았다.
- 웹 서버는 로컬 토큰 방식의 **127.0.0.1 전용**이다. 공용 웹서비스 로그인·권한·외부 배포는 아직 없다.
